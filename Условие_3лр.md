# План выполнения Лабораторной работы №3

**Тема:** Реализация программного компонента системы искусственного интеллекта  
**Цель:** Превратить архитектуру из ЛР №2 в работающий и протестированный изолированный Python-компонент.

---

## 1. Подготовка и Окружение
-  **Шаг 1. Выбрать минимальную функцию.** Выбрать 1 компонент из ЛР №2 и выписать: назначение, поля входа/выхода, логику модели, бизнес-правила и условия отказа/ревью человеком.
- [ ] **Шаг 2. Создать ветку в Git.** `git switch -c feature/lab3-component`
- [ ] **Шаг 3. Изолировать окружение.** Создать `.venv`, активировать и установить `pytest`, `pydantic` и библиотеки для модели.
- [ ] **Шаг 4. Создать структуру проекта:**
  ```text
  app/
    ├── schemas.py        # Входной и выходной контракты (Pydantic)
    ├── preprocessing.py  # Преобразование данных и нормализация
    ├── inference.py      # Вызов модели / интеллектуальная функция
    └── service.py        # Прикладные бизнес-правила
  tests/
    └── test_component.py # Минимум 4 теста (pytest)
  docs/
    └── lab3_report.md    # Отчет по работе
  ```

## 2. Реализация кода и Контракта
- [ ] **Шаг 5. Описать контракт.** Строгие типы данных, валидация диапазонов, фиксация версии модели, флаг `needs_human_review`.
- [ ] **Шаг 6. Реализовать пайплайн.** Чистый конвейер: *Вход → Проверка → Подготовка → Модель/Поиск → Прикладное правило → Результат*.
- [ ] **Шаг 7. Интегрировать baseline-модель.** Использовать готовый легкий артефакт (не заглушку вроде `return "NORMAL"`). Запрещено заново обучать или рассчитывать параметры нормализации внутри единичного запроса.
- [ ] **Шаг 8. Внедрить бизнес-правило.** Отделить вывод AI от финального решения (например: если уверенность низкая — отправить человеку, если объект найден — применить регламент).

## 3. Тестирование и Безопасность
- [ ] **Шаг 9. Написать 4 обязательных теста (pytest):**
  1. Корректный запрос №1 → Ожидаемый валидный результат.
  2. Корректный запрос №2 → Другой ожидаемый результат.
  3. Неверный/пограничный вход → Контролируемая ошибка/обработка.
  4. Сбой модели/нет файла весов → Явный отказ (без ложного успеха).
- [ ] **Шаг 10. Изолировать сеть.** Заглушить (mock) внешние AI API в тестах (тесты не должны зависеть от интернета и тратить токены).
- [ ] **Шаг 11. Проверить безопасность.** Убедиться, что в репозиторий **НЕ** попали: папка `.venv/`, `.env` файлы, API-ключи, реальные персональные данные и опасные форматы моделей (`.pickle`/`.joblib`).

## 4. Демонстрация и Сдача
- [ ] **Шаг 12. Подготовить демо для преподавателя.** Быть готовым показать: 2 правильных входа, 1 ошибочный, случай передачи человеку, вывод тестов.
- [ ] **Шаг 13. Оформить отчет `docs/lab3_report.md`** (Тема, место в архитектуре, контракт, описание модели, таблица тестов, ограничения).
- [ ] **Шаг 14. Сделать Commit и Push:**
  ```bash
  git add app tests docs/lab3_report.md
  git commit -m "feat: implement tested AI component for lab 3"
  git push -u origin feature/lab3-component
  ```
- [ ] **Шаг 15. Открыть Pull Request.** Создать PR из ветки `feature/lab3-component` в `main` и отправить ссылку преподавателю.

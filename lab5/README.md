# Smart Helpdesk. ЛР 7

[![ML System CI/CD](https://github.com/ovv20062009-afk/Smart-Helpdesk/actions/workflows/ml-ci-cd.yml/badge.svg)](https://github.com/ovv20062009-afk/Smart-Helpdesk/actions/workflows/ml-ci-cd.yml)

Сервис определяет тему обращения и предлагает отдел. ЛР 7 продолжает исходники ЛР 5 и 6 в этой папке. Добавлены Bearer-аутентификация, проверка права на прогноз, квота и версионный API. Модель осталась прежней: v1.4.0, TF-IDF из ЛР 4 и LogisticRegression. API v1 обозначает версию контракта, а не новое обучение модели.

[Отчёт ЛР 7](../docs/lab7_report.md), [Model Card](../MODEL_CARD.md), [отчёт ЛР 6](../docs/lab6_report.md).

## 1. Подготовка

Команды ниже выполняются в Windows CMD из папки lab5. Если виртуальное окружение уже существует, создавать его повторно не нужно.

```cmd
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe prepare_artifacts.py
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe configure_local.py init
```

Версии библиотек закреплены в requirements.txt и requirements-dev.txt. Для подготовки нужны результаты ЛР 4: train.parquet, test.parquet и preprocessor.joblib. Восстановление описано в ../lab4/README.md. На запросе модель не обучается.

configure_local.py создаёт локальный .env с двумя случайными токенами. APP_DEMO_TOKEN разрешает прогноз, APP_READONLY_TOKEN обозначает известного клиента без такого права. Оба значения остаются на компьютере. Файлы .env и .env.* исключены из Git, кроме пустого шаблона .env.example.

Сервис читает токены из переменных окружения при старте. Docker получает их через --env-file. Python сам не читает .env; для запуска без Docker это явно делает configure_local.py serve. После смены токенов сервис нужно перезапустить.

## 2. Запуск в Docker

Если контейнер ЛР 6 ещё занимает порт 8000, остановите его:

```cmd
docker stop smart-helpdesk-lab6
docker stop smart-helpdesk-lab6-fallback
```

Соберите образ с обновлённым API и запустите новый контейнер. Тег v1.4.0 сохранён по версии комплекта модели, поэтому после изменений сборка обязательна.

```cmd
docker build --progress=plain -t smart-helpdesk:v1.4.0 .
docker run -d -p 127.0.0.1:8000:8000 --env-file .env --name smart-helpdesk-lab7 smart-helpdesk:v1.4.0
.venv\Scripts\python.exe record_docker.py
```

Ожидаются 6 успешных сетевых тестов. Результаты попадут в docs/lab7/container_tests.txt и docker_result.json. Если имя контейнера занято, сначала посмотрите docker ps -a. Повторно создавать уже работающий контейнер не нужно.

Один контейнер запускает один worker. Вызов модели и изменение её состояния защищены Lock. Это простой способ согласовать состояние учебного сервиса, он ограничивает параллельные расчёты. Перед увеличением нагрузки нужны измерения.

## 3. Запуск без Docker

```cmd
.venv\Scripts\python.exe configure_local.py serve
```

Команда явно читает локальный .env, передаёт токены дочернему процессу Uvicorn и запускает один worker на 127.0.0.1:8000. Одновременно запускать контейнер на этом же порту не нужно.

## 4. Swagger и настоящий запрос

Откройте http://127.0.0.1:8000/docs. Для получения локального токена выполните:

```cmd
.venv\Scripts\python.exe configure_local.py show-token
```

Скопируйте значение, нажмите Authorize, вставьте только токен без слова Bearer, подтвердите авторизацию и закройте окно. Не включайте токен в скриншот или отчёт.

Выберите POST /api/v1/predict, затем Try it out. Вставьте:

```json
{
  "ticket_id": "T-7",
  "text": "Не могу войти, забыла пароль",
  "channel": "web"
}
```

Нажмите Execute. Ожидается 200, category=TECHNICAL, source=model и degraded=false. Отдел зависит от оценки и порога 0.8: ниже порога будет OPERATOR. trace_id в теле совпадает с X-Trace-ID в заголовке. Этот же идентификатор можно найти в JSON-логе.

Сохраните скриншот ответа и скриншот /ready без окна авторизации. Это ручная часть демонстрации; автоматическая проверка схемы не заменяет её.

## 5. Вход и ответ

| Поле | Ограничение |
|---|---|
| ticket_id | Обязательно, строка от 1 до 100 символов: латиница, цифры, дефис, подчёркивание |
| text | Обязательно, строка от 1 до 5000 символов, после очистки должны остаться слова |
| channel | web, email или chat; при отсутствии используется web; null запрещён |
| Любое другое поле | Запрещено |

ticket_id не включается в признаки. В модели используются текст и канал в том же порядке и с теми же преобразованиями, что при обучении. Для нашей темы device_id из примера методички заменён на ticket_id, а параметры оборудования на text и channel. Целевая переменная: категория TECHNICAL, PAYMENT или STUDY. Целевая метка не передаётся во входе API.

Ответ содержит trace_id, ticket_id и два блока. В prediction находятся category, confidence, destination, manual_review_required, threshold_used и matched_words. В metadata находятся model_version, preprocessor_version, timestamp_utc, latency_ms, source и degraded.

confidence является максимальной оценкой predict_proba по фактическим classes_ модели. Калибровка не проверялась, поэтому это не гарантированная вероятность правильного ответа. При неизвестных словах и в резервном режиме значение равно null. Порог 0.8 является учебной настройкой маршрутизации из предыдущих работ. Для Fallback действует отдельное правило двух разных ключевых слов, threshold_used к нему не применяется.

source=model сохранено для совместимости с ЛР 6. В примере методички это же состояние названо ml_model. source=fallback_rule означает резервное правило, degraded=true. latency_ms включает ожидание блокировки, расчёт и проверку результата алгоритма; это не полное время запроса по сети. timestamp_utc относится к формированию ответа.

## 6. Адреса и HTTP-статусы

| Адрес | Доступ и поведение |
|---|---|
| GET /health | Без токена, HTTP 200, процесс отвечает; при сбое модели status=degraded |
| GET /ready | Без токена, 200 при готовой модели и настроенном доступе, иначе 503 |
| POST /api/v1/predict | Bearer-токен, право прогноза, общая квота клиента |
| POST /predict | Старый плоский формат, те же токен и квота; помечен deprecated |
| GET /docs и /openapi.json | Без токена; схемы и кнопка Authorize |

| Код | Что означает |
|---|---|
| 200 | Получен результат модели либо явно обозначенный Fallback |
| 401 | Нет токена, токен неверен или использована другая схема; есть WWW-Authenticate: Bearer |
| 403 | Токен известен, но клиенту запрещён прогноз |
| 422 | Запрос не соответствует схеме |
| 429 | Квота исчерпана, Retry-After сообщает число секунд до допуска |
| 503 | Доступ не настроен, /ready не готов либо расчёт и резервное правило недоступны |

/ready возвращает 503 при отсутствующих артефактах, последнем сбое модели или отсутствии APP_DEMO_TOKEN. Одинаковые токены двух ролей также считаются ошибкой настройки. После успешного повторного прогноза временный сбой снимается. До этого model_loaded может быть true, а model_ready false: файл загружен, но последний расчёт завершился ошибкой.

## 7. Квота

Скользящее окно допускает 60 обращений известного клиента за последние 60 секунд. Проверка и запись защищены Lock. Используется monotonic, а не календарное время. Отклонённый по квоте запрос не добавляется в историю. Retry-After рассчитывается по самому раннему действующему допуску.

Считаются прохождения проверки доступа. Разрешённый, но невалидный запрос с ответом 422 тоже может занять допуск. Успешный Fallback и отказ вычисления после допуска также считаются. 401 и 403 квоту не расходуют. Старый и новый адреса делят один счётчик, /health и /ready квоту не расходуют.

У клиентов с одним общим токеном общая квота. Память очищается при перезапуске. Несколько процессов не делят историю. Здесь всего два заранее известных клиента, поэтому словарь не растёт от произвольных токенов. Это не общая квота кластера и не полноценная защита от DDoS. Всплеск из 60 запросов допускается; одна операция в секунду не гарантируется.

## 8. Проверка доступа и квоты настоящими HTTP-запросами

При работающем обычном контейнере:

```cmd
.venv\Scripts\python.exe record_rest.py
```

Скрипт явно читает .env, проверяет настоящую модель, отсутствие и ошибку токена, запрет действия, неверный вход и исчерпание квоты. Сохраняет docs/lab7/http_protocol.json с ожиданием и фактическим кодом, а также real_model_response.json. Токены в результат не записываются.

После проверки квота намеренно исчерпана. Дождитесь указанного Retry-After либо перезапустите только учебный контейнер:

```cmd
docker restart smart-helpdesk-lab7
```

Если до record_rest.py квота уже исчерпана, выполните эту команду перед проверкой.

## 9. Проверка резервного режима

```cmd
docker run -d -p 127.0.0.1:8001:8000 --env-file .env -e HELPDESK_DISABLE_MODEL=1 --name smart-helpdesk-lab7-fallback smart-helpdesk:v1.4.0
.venv\Scripts\python.exe record_rest.py --fallback
```

Ожидаются 6 успешных сетевых тестов, /health с HTTP 200, /ready с 503 и прогноз с 200, source=fallback_rule, degraded=true, confidence=null. Для двух слов «войти» и «пароль» правило предлагает IT_SUPPORT. Результат сохраняется в docs/lab7/fallback_response.json.

Модель и препроцессор загружаются один раз при старте. Отсутствие файлов или сбой predict_proba включает прежний Fallback. Если сломано и резервное правило, прогноз отвечает 503, а не возвращает выдуманную оценку.

## 10. Логи и тесты

```cmd
docker logs smart-helpdesk-lab7 > docs\lab7\container_logs.jsonl 2>&1
.venv\Scripts\python.exe check_json_logs.py docs\lab7\container_logs.jsonl
docker logs smart-helpdesk-lab7-fallback > docs\lab7\fallback_logs.jsonl 2>&1
.venv\Scripts\python.exe check_json_logs.py docs\lab7\fallback_logs.jsonl
```

Вторым аргументом check_json_logs.py можно указать trace_id из ответа. Скрипт проверит все строки и наличие этого идентификатора. Токены, исходные тексты и тела запросов не записываются в JSONL. В PowerShell вместо перенаправления CMD используйте Set-Content -Encoding utf8.

При подготовке прошли 87 тестов Python и по 6 сетевых проверок модели и Fallback без Docker. Истечение окна проверяется управляемыми часами без ожидания минуты. Конкурентная проверка подтверждает, что несколько потоков не превысят число допусков. Основной сквозной тест использует настоящий артефакт; подмены ошибок в тестах указаны явно.

Журнал резервного контейнера содержит 27 валидных JSON-строк и 19 записей запросов, идентификатор ответа найден.

Через Swagger выполнены POST /api/v1/predict с настоящей моделью и GET /ready, оба вернули 200. Оценка 0.7279 ниже порога 0.8, поэтому обращение передано оператору. Подробности и ответы без секретов находятся в [результатах Windows](docs/lab7/windows_checks.md) и [отчёте](../docs/lab7_report.md). ## 11. CI/CD и сдача

Workflow ../.github/workflows/ml-ci-cd.yml выполняет линтинг, тесты прежних работ, подготовку модели, проверки REST API и сборку. Временные токены генерируются при запуске и маскируются в журнале Actions. В Docker передаются переменные окружения, секреты не добавляются в образ.

Проверяются обычный контейнер, Fallback, JSONL, доступ и квота. Образ и Model Card сохраняются как smart-helpdesk-image-SHA, результаты как lab7-verification-SHA. Новому workflow нужно пройти проверку после публикации ветки. Успех ЛР 6 не означает, что изменения ЛР 7 уже проверены на GitHub.

Перед сдачей сохраните ручные скриншоты Swagger без секретов и протокол своих проверок. В отчёте отделены результаты подготовки от действий, которые ещё нужно выполнить на Windows.

Ограничения: учебные постоянные токены без срока действия и ротации, два локальных клиента, один worker, лимитер в памяти, искусственные данные и малая тестовая выборка. HTTPS, управление учётными записями, распределённый лимитер и внешнее развёртывание не реализованы.

# ЛР 4. Подготовка данных Smart Helpdesk

Здесь находится конвейер подготовки обращений для будущего обучения модели. Он проверяет CSV, очищает тексты, удаляет повторы, разделяет данные по времени и сохраняет признаки вместе с препроцессором.

Работа продолжает тему № 4 из ЛР 2 и 3. Пример с телеметрией из методички адаптирован под тексты обращений. Замена предметной области должна быть допустима по требованиям преподавателя.

## Что находится в папке

| Файл | Для чего нужен |
|---|---|
| src/make_sample.py | Создаёт одинаковый учебный CSV при каждом запуске |
| src/contracts.py | Описывает проверку исходных данных через Pandera |
| src/preprocessing.py | Очищает текст и вычисляет его длину |
| src/pipeline.py | Выполняет подготовку и записывает запуск в MLflow |
| src/demo.py | Применяет сохранённый препроцессор к новому обращению |
| src/run_dvc.py | Запускает DVC с правильным Python на Windows и Linux |
| src/check_pipeline.py | Проверяет реакцию DVC на изменение и ошибку в CSV |
| tests/test_pipeline.py | Проверяет контракты, очистку, split и сохранение |
| params.yaml | Доля train и настройки TF-IDF |
| dvc.yaml и dvc.lock | Этап подготовки, зависимости и контрольные суммы |
| data/raw/tickets.csv.dvc | DVC-указатель на исходный CSV |
| docs/lab4_report.md | Отчёт и ответы на контрольные вопросы |
| docs/mlflow_run.json | Экспорт параметров, метрик и списка артефактов проверенного запуска |

## Данные и контракт

Учебные фразы написаны для этой работы. Реальных обращений и персональных сведений в наборе нет.

| Поле | Ограничение |
|---|---|
| ticket_id | Уникальная строка вида T-0001 |
| created_at | Дата и время обращения |
| text | Строка до 5000 символов; пропуски и пустые тексты удаляются при очистке |
| channel | web, email или chat; пропуск заполняется по train |
| category | TECHNICAL, PAYMENT или STUDY; обязательная метка |

Лишние столбцы, неизвестные категории, неверные даты и идентификаторы блокируют подготовку. Отсутствующий текст разрешён в исходном контракте, чтобы его можно было явно удалить и посчитать. Неверные метки не заменяются выдуманными значениями.

## Запуск в PowerShell

Нужен установленный Git и Python 3.12. Команды выполняются из папки Smart-Helpdesk. В ней уже должен находиться Git-репозиторий ЛР 2 и 3.

Каждую строку выполняйте отдельно:

```powershell
cd C:\Users\liza_\Smart-Helpdesk
cd lab4
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m src.make_sample
.\.venv\Scripts\python.exe -m src.run_dvc repro
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m src.demo
```

В поставке уже есть служебные файлы DVC, созданные командой `dvc init --subdir`, поэтому повторная инициализация не требуется. Подпроект находится внутри общего Git-репозитория Smart-Helpdesk. Окружение ЛР 4 создаётся внутри lab4 и не меняет окружение ЛР 3.

`run_dvc` нужен из-за возможного псевдонима `python` в Windows. Он добавляет Python текущего окружения в PATH дочернего процесса. Если окружение уже активировано, обычная команда `dvc repro` выполняет тот же конвейер.

CSV и результаты подготовки не включаются в Git. Небольшой исходный набор восстанавливается из src/make_sample.py. Его версия зафиксирована указателем DVC. Удалённое хранилище в учебной работе не настроено; выполнять `dvc pull` или `dvc push` не нужно. При работе с настоящим закрытым набором понадобится отдельное DVC-хранилище.

После намеренного изменения исходных данных зафиксируйте новую версию:

```powershell
.\.venv\Scripts\python.exe -m src.run_dvc add data/raw/tickets.csv
.\.venv\Scripts\python.exe -m src.run_dvc repro
```

## Что получается

| Результат | Содержание |
|---|---|
| data/processed/train.parquet | Признаки и метки обучающей выборки |
| data/processed/test.parquet | Признаки и метки тестовой выборки |
| data/processed/validation_report.json | Число строк, удалённых записей, признаков и пересечений |
| data/processed/split_ids.json | Идентификаторы обращений в каждой выборке |
| artifacts/preprocessor.joblib | Один объект с TF-IDF, масштабированием длины и кодированием канала |
| artifacts/feature_names.json | Названия признаков в порядке столбцов |
| data/processed/mlflow_run.json | Экспорт запуска MLflow |

Исходно 64 строки. Удаляются 2 пустых обращения и 2 повтора. Остаются 60 обращений: 48 ранних для train и 12 поздних для test. В проверенной версии получается 302 признака, пропусков и одинаковых очищенных текстов между выборками нет.

Сначала выполняется split. Затем `fit_transform` вызывается только для train. На test и на новых обращениях вызывается только `transform`. Метки, идентификаторы и даты не входят в признаки. Дата используется для разделения, метка сохраняется отдельно.

Препроцессор содержит собственную функцию очистки текста. Для его загрузки нужен код пакета src и то же окружение. Загружайте только созданные вами доверенные joblib-файлы.

Это этап подготовки данных. Обучение классификатора и подключение нового препроцессора к API ЛР 2 пока не выполняются. Компонент ЛР 3 продолжает работать отдельно.

## Проверка DVC

```powershell
.\.venv\Scripts\python.exe -m src.check_pipeline
```

Скрипт проверяет три ситуации: повтор без изменений, изменение текста и недопустимую метку категории. Исходный CSV восстанавливается даже при ошибке проверки. Результаты сохраняются в docs/check_results.json, вывод команд в docs/dvc_checks.txt.

Не запускайте проверку одновременно с редактированием CSV. Перед демонстрацией реальные рабочие данные должны быть сохранены отдельно: проверка рассчитана на учебный набор.

## Просмотр MLflow

Из папки lab4:

```powershell
.\.venv\Scripts\python.exe -m mlflow ui --backend-store-uri sqlite:///mlflow.db --host 127.0.0.1 --port 5000
```

Откройте http://127.0.0.1:5000. Выберите эксперимент `lab4-smart-helpdesk`, затем нужный запуск. В нём записаны параметры разделения и TF-IDF, контрольная сумма CSV, метрики подготовки и пять артефактов.

Для сдачи можно приложить экспорт docs/mlflow_run.json. Он уже включён в проект. База mlflow.db и папка mlruns остаются локально.

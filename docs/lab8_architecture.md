# Архитектура ЛР 8

Браузер показывает форму Streamlit. После нажатия кнопки серверный Python-процесс Streamlit вызывает api_client.py. Затем запрос по HTTP поступает в FastAPI из ЛР 7. Сервер проверяет Bearer-токен, право прогноза, квоту и данные, после чего вызывает адаптер модели. Ответ проверяется клиентской схемой и только потом показывается на странице.

| Компонент | Обязанность |
|---|---|
| frontend/app.py | Форма, состояния, результат и история сеанса |
| frontend/api_client.py | HTTP, таймауты, ошибки и связь ответа с обращением |
| frontend/request_validation.py | Проверка формы по полям ЛР 7 |
| frontend/response_validation.py | Копия контракта, диапазоны и согласованность ответа |
| frontend/history.py | Ограниченная история, разрешённые поля и CSV |
| frontend/run_ui.py | Явная настройка API_URL и API_TOKEN для дочернего Streamlit |
| lab5/src/api.py | REST API, доступ, квота, trace_id и обработка отказов |
| lab5/src/model_adapter.py | Сохранённые модель и препроцессор |

Модель и joblib-файлы не загружаются в frontend. API-клиент не импортирует Streamlit и не строит страницу. Схемы клиента не импортируют код сервера: их совместимость проверяется тестами и настоящим HTTP.

В HTTP участвуют два серверных процесса. requests выполняется процессом Streamlit, а не JavaScript браузера. Поэтому localhost в настройке API_URL относится к машине Streamlit. В этой лабораторной оба приложения запускаются локально. CORS для серверного requests не требуется. Межконтейнерные адреса и внешнее размещение отдельно не настраивались.

API_URL задаёт базовый адрес API, API_TOKEN используется только для заголовка Authorization. run_ui.py явно получает локальный токен из окружения или lab5/.env и передаёт процессу Streamlit. Токен не включается в страницу, payload, историю и CSV. Локальный HTTP допустим в этом учебном запуске; для внешней сети нужен защищённый транспорт.

Оба API сохраняют прежнюю семантику ЛР 7. /health проверяет процесс, /ready проверяет модель и настройку доступа. При намеренно отключённой модели /ready имеет 503, а согласованный Fallback может дать 200 на прогноз. Интерфейс различает модель, резервный результат и ошибку без результата.

Клиент измеряет время попытки целиком со своей стороны. server_ms в истории приходит от API и не включает сетевой обмен. Эти значения нельзя считать одним и тем же измерением.

# Проверки ЛР 8

Среда подготовки: Linux, Python 3.12. Streamlit 1.51.0. Результаты не выданы за запуск на Windows. Ручная проверка Windows выполнена отдельно, её результаты приведены ниже.

| Сценарий | Ожидание | Фактический результат и способ проверки |
|---|---|---|
| Валидная форма | Ответ модели с версией, оценкой и UUID | Выполнено через AppTest и настоящий HTTP к ранее обученной модели |
| Новое обращение | Новый UUID и правильный ticket_id | Выполнено двумя реальными запросами формы |
| Неверный токен | Ошибка 401 без карточки прежнего успеха | Выполнено через настоящий HTTP; в форме нет метрики |
| API недоступен | Понятное сообщение без оценки | Выполнено с настоящим локальным портом без слушателя; сервер не объявляется остановленным |
| Таймаут | Нет фиктивного результата | Явная подмена requests.Timeout в тестах клиента и ошибка ожидания в тесте формы |
| Fallback | Предупреждение, confidence=null | Настоящий HTTP к API с HELPDESK_DISABLE_MODEL=1 |
| 429 | Ошибка с Retry-After, без скрытых повторов | Настоящая квота заполнена намеренно; подсказка показана формой |
| Неверный JSON и нарушенный контракт | Ошибка интеграции | Явные подмены json() и тела ответа в автоматических тестах |
| История | Успехи и ошибки в одном сеансе | В сквозном тесте сохранены шесть попыток |
| CSV | Читается, есть входы и результат, нет токена | Реальный CSV прочитан через csv.DictReader, поля ошибок пустые, токена нет |
| Защита CSV от формул | Опасное начало текстовой ячейки экранировано | Проверены =, +, -, @, начальные пробелы и управляющие символы |
| Лимит истории и очистка | Не больше 100 строк, очистка работает | Проверены автоматически |
| Запуск Streamlit | Процесс отвечает | GET / и /_stcore/health вернули 200 |

Автотесты клиента и формы: 73 passed. Повторная установка в чистое отдельное окружение и все 73 теста также прошли; вывод сохранён в pytest_clean_environment.txt. Линтинг: All checks passed. Эти проверки не измеряют качество модели. Модельная оценка взята из ранее созданных артефактов, случайные числа и заглушка в сквозном сценарии не использовались.

Файлы подтверждения:

- pytest_results.txt и lint.txt: вывод автоматических проверок.
- live_protocol.json: фактический протокол AppTest с настоящим HTTP.
- real_ui_response.json и fallback_ui_response.json: реальные ответы без токенов.
- ui_history.csv: шесть попыток, включая ошибки и резервный режим.
- api_model_logs.jsonl и api_fallback_logs.jsonl: журналы API при подготовке.
- streamlit_health.txt: фактическая доступность процесса Streamlit.

Тесты повторяются командой `python -m pytest tests_frontend -q` из корня. Сквозной протокол повторяется `python -m frontend.verify_live` при работающих двух API. Окружение интерфейса должно содержать зависимости frontend/requirements.txt. Скрипт явно читает локальную конфигурацию, секреты не выводит.

При повторном запуске файлы протокола заменяются новыми фактическими результатами. Время client_ms зависит от среды. Число строк JSONL относится к моменту снятия журнала. Запуск Windows и четыре браузерных сценария подтверждены; проверка CI нового коммита выполняется после публикации.

73 теста прошли за 11.10 с. Запущены форма и API, /ready подтвердил готовность. Ручная проверка дала следующие результаты:

| Сценарий | Ожидание | Получено |

frontend.verify_live также завершился успешно: шесть сценариев passed. Проверены новый UUID, настоящий отказ доступа, порт без слушателя, резервный API, реальная квота с Retry-After: 57 и CSV с шестью попытками без токена.

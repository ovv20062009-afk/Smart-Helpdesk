# Проверки ЛР 8 на Windows

Дата: 22.11.2026. Использованы Windows, Python 3.12.2, отдельное окружение .venv-ui, Streamlit и Docker API из ЛР 7.

| Проверка | Фактический результат |
|---|---|
| Автоматические тесты frontend | 73 passed за 11.10 с |
| Готовность модели перед запуском | /ready: status=ready, модель и препроцессор загружены, доступ настроен |
| Форма в браузере | Отправлено T-8, технический вопрос, оценка 0.728, маршрут «Оператор», source=model, v1.4.0 |
| Остановка основного API | Для T-9 показаны отказ соединения и отсутствие оценки; старое значение не отображается |
| История браузерного сеанса | Видны T-8 с оценкой 0.7279 и T-9 с ошибкой connection без оценки |
| Резервная форма | Предупреждение, маршрут «Техническая поддержка», source=fallback_rule, численная оценка отсутствует |
| frontend.verify_live | Все шесть сценариев passed |
| Два настоящих запроса формы | Новый UUID, правильный номер обращения |
| Неверный токен | Ошибка доступа после прежнего успеха без старой метрики |
| Недоступный адрес | Реальный порт без слушателя, сообщение об отказе соединения |
| Резервный API | Настоящий HTTP с HELPDESK_DISABLE_MODEL=1 |
| Квота | Показана ошибка 429, Retry-After: 57 |
| История и CSV сквозной проверки | Шесть попыток, CSV прочитан csv.DictReader, оценки ошибок пустые, токена нет |

При запуске AppTest появилось предупреждение missing ScriptRunContext. Проверка завершилась без ошибки, все сценарии получили passed.

Фактический вывод сквозной проверки сохранён в windows_live_protocol.json. Скрипт на компьютере также записал live_protocol.json, real_ui_response.json, fallback_ui_response.json и ui_history.csv. Эти файлы не заменяются архивом обновления отчёта.

Скриншоты браузерной проверки:

- ui_model.png: настоящая модель, UUID fb4752fe-b3b4-4f5c-9583-9785269119ad.
- ui_connection_error.png: ошибка соединения для T-9 после остановки API.
- ui_history.png: успешная попытка и ошибка в одном сеансе.
- ui_fallback.png: резервное правило, UUID 59098bb4-956e-48d1-8f0b-c77d31ad87c0.

Резервное правило и модель проверялись разными запусками интерфейса. Ручная ошибка проверена остановкой контейнера. В автоматическом сквозном сценарии отказ соединения воспроизведён через порт без слушателя. Таймаут и неверный JSON проверялись явными подменами в автотестах, а не реальным аппаратным отказом.

Осталось подтвердить успешный CI коммита ЛР 8 после публикации. Успешный CI ЛР 7 не подменяет эту проверку.
